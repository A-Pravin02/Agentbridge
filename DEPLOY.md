# Deploy — two steps, both free, no card

For an online hackathon the judges need a URL. This is the shortest path that
works, and it avoids the monorepo auto-detection that made Railway fail.

**Total: about 10 minutes.**

---

## Step 1 — API on Render (~5 min)

Render reads `render.yaml` and configures everything itself, so there are no
build settings to get wrong.

1. Go to **[render.com](https://render.com)** and sign up with GitHub. No card.
2. **New → Blueprint**
3. Select the **Agentbridge** repo → **Connect**
4. Render finds `render.yaml` and shows one service, `agentbridge-api`. It will
   ask for the two values marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Your Neon connection string (production branch) |
   | `ALLOWED_ORIGINS` | `https://placeholder.vercel.app` — corrected in step 3 |

   The three secrets are generated by Render. You never see or handle them.
5. **Apply**. First build takes 5–8 minutes.

Your API URL will be `https://agentbridge-api.onrender.com` (or similar).

**Verify:**

```
https://agentbridge-api.onrender.com/api/ready
```

Expected: `{"status":"ready","database":"connected"}`

That endpoint returns 503 unless the database genuinely answers, so a 200 means
it actually works — not merely that the container started.

---

## Step 2 — Dashboard on Vercel (~3 min)

1. Go to **[vercel.com](https://vercel.com)** and sign up with GitHub.
2. **Add New → Project** → import **Agentbridge**
3. **Root Directory: `apps/web`** ← the step people miss. Click *Edit* next to
   Root Directory and select `apps/web`.
4. Environment Variables — add one:

   | Name | Value |
   |---|---|
   | `NEXT_PUBLIC_API_URL` | Your Render URL, no trailing slash |

5. **Deploy**

---

## Step 3 — Close the CORS loop (~1 min)

The API refuses browser requests from unknown origins, so it has to be told the
dashboard's real address.

Render → `agentbridge-api` → **Environment** → set:

```
ALLOWED_ORIGINS=https://your-actual-app.vercel.app
```

Save. Render redeploys. **Give the judges the Vercel URL.**

---

## The first visit takes ~30 seconds

Render's free tier sleeps after 15 minutes idle. The first request wakes it,
which takes roughly 30 seconds.

The dashboard handles this deliberately:

- It pings the API the moment the page loads, so the container starts booting
  while the visitor is still reading the sign-in screen.
- Requests that fail in a way consistent with a sleeping server are retried with
  backoff for up to 90 seconds.
- A banner explains what is happening, rather than showing an error or a spinner
  that looks like a hang.

**Before judging, open the URL once yourself.** It then stays warm for 15
minutes and the judges get an instant load.

## What the judges should do

1. Open the Vercel URL
2. Sign in: `owner@techkart.demo` / `techkart-demo-2026`
3. **Attack console → Run all scenarios**

Fourteen scenarios run as real signed HTTP requests through the real stack. Ten
are attacks. Expected: **14/14 passed, 10/10 attacks stopped.**

Then **Transactions → click any row** for the decision timeline: all fifteen
policy rules with pass/fail, the risk factors, and the hash-chained audit trail
with its integrity verified.
